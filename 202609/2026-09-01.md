### 1. DeepSeek 在 Hugging Face 开源 V4 家族首个多模态权重 DeepSeek-V4-Flash-Vision-Exp
- 类型：工程
- 来源：Hugging Face 模型卡 deepseek-ai/DeepSeek-V4-Flash-Vision-Exp + DeepSeek API 文档 Vision 页；中文对照 IT之家 / 2026-08-31
- 发布日期：权重 2026-08-31（HF）；API 上线 2026-08-21
- 链接：https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-Vision-Exp
- 阅读置信度：全文（模型卡、API 文档）；IT之家为对照
- 一句话：DeepSeek 把 V4-Flash 的实验性视觉版以 MIT 放出：权重、Tokenizer、Prompt 编码参考和最小 PyTorch 推理一起给，官方评测表上多模态 Agent 分接近 Opus-4.8，纯文本分与 V4-Flash-0731 持平或略升。
- 中心思想：模型卡写明这是 V4 家族第一个实验性多模态模型，在 V4-Flash 上加视觉模块并继续训练。官方对照表用 DeepSeek Harness 的 minimal 模式、`max` reasoning、`temperature=1.0`、`top_p=0.95`。ApexBench Pass@1 为 36.5，对标 Opus-4.8 的 39.4；Agents' Last Exam 27.3，略高于 Opus-4.8 的 25.7。纯文本侧 Terminal Bench 2.1 为 83.9（0731 为 82.7，Opus-4.8 为 85.0）。0731 在 ApexBench / Agents' Last Exam 上「忽略输入里的多模态元素」，所以 26.2→36.5 不是同条件视觉对比。
- 关键要点：
  - HF 模型卡：MIT License；仓库含视觉编码器、Aligner、DFlash Attention、MoE、Hyper-Connections、DSpark 前向路径的最小实现；Safetensors 页写 Model size 305B params
  - 调用名 `deepseek-v4-flash-vision-exp`。图只允许出现在 `user` 消息；`system` / `assistant` 带图返回 400。支持 JPEG / PNG / GIF / WebP，按文件内容识别，不看扩展名
  - 三种送图：inline base64、公开 URL（最长 8192 字符、单图 32 MiB、下载 60 秒）、Files API `file_id`（单图可到 64 MiB）。请求体 48 MiB；单请求最多 600 张图
  - 计费：图按尺寸转成 input token，与文本同价。默认会把大图缩到大约 800×800 总像素，每张图上限 384 token；2000×2000 和 5000×5000 消耗可以相同。`detail=low` 先缩到 512×512
  - 文本对照（官方表）：DeepSWE 59.3 vs 0731 的 54.4 vs Opus-4.8 的 58.0；Toolathlon-Verified 75.9 vs 70.3 vs 76.2。NL2Repo 57.7，仍低于 Opus-4.8 的 69.7
- 关键数据/指标：上表数字均为 DeepSeek 官方评测，未经独立复测。HF 写 305B；部分第三方把纯文本 V4-Flash 写成 284B-A13B，视觉模块是否另计，模型卡未拆
- 技术或产品细节：Prompt 同时接受 OpenAI 风格 JSON content block 和紧凑 TXT 路径记号。另有 Anthropic 兼容 `/messages` 和 OpenAI Responses API。API 文档写 FIM 等能力以该模型页为准；eesel 等二手稿称 Vision-Exp 不提供纯文本 V4-Flash 的 FIM，本条未打开价格卡逐条核对
- 开发者可带走：截图 Agent、浏览器轨迹这类「一张图几百 token」的负载，先拿 API 跑通再决定要不要下 305B 权重。评测数字只在 Harness minimal + `max` 档下成立，换框架不要直接对标 Opus-4.8
- 边界与风险：名字带 Exp，没有 0731 那种日期钉。官方「接近 Opus-4.8」是四项多模态分里 2 胜 2 负量级，不是全面持平。本机推理的显存、量化配方模型卡未给
- 为何重要：开源侧第一次把 V4 的 Agent 文本能力和可计费视觉输入绑在同一条 MIT 链路上，Computer Use / Coding Agent 的截图成本可以按每张 ≤384 token 估算

### 2. OpenClaw 发布 2.0（v2026.8.1）：933 名贡献者、超过 1.6 万个 PR，安装与浏览器端重做
- 类型：工程
- 来源：OpenClaw 官方博客《OpenClaw 2.0, Accidentally》+ 发布说明 v2026.8.1；中文对照微信公号「机器之心Pro」（网易号 2026-08-31）、新智元（网易号 2026-09-01）
- 发布日期：2026-08-30（官方）；中文 2026-08-31 / 09-01
- 链接：https://openclaw.ai/blog/openclaw-2-accidentally
- 阅读置信度：全文（官方博客、机器之心Pro 转载页）；发布说明体量极大，本条未逐条打开全部 PR 列表
- 一句话：官方把 2.0 写成「本来只想简化安装、重做浏览器，清着清着变成大版本」；项目统计 933 名贡献者（含 569 名首次提交）、合并 PR 超过 1.6 万，约占历史合并量一半。
- 中心思想：此前近七周没发版；再往前 230 天发过 106 个版本。博客说团队变大后，工作量超出旧底座和发版流程，两边一起返工。新安装先扫描本机已有的 Codex / ChatGPT / Claude CLI 登录、API key、Ollama / LM Studio，验证能应答再落盘。浏览器 Control UI 改成 chat-first；机器之心Pro 转述模拟环境（mocked Gateway、50 ms HTTP/1.1）下 JS 请求 140→45、启动约 1.6 秒→575 毫秒。
- 关键要点：
  - 会话和转录迁入 SQLite。回滚到文件存储前必须用当前 CLI 恢复归档转录；迁移后新建的会话在旧版本里不会出现。官方建议升级前做一次经验证的备份
  - 共享云会话：所有者或管理员可设只读、建议、草稿或直接参与。文档写明这些控制不是租户隔离、不构成安全边界，权限撤销后界面刷新前仍可能显示为可用
  - Incognito 默认关：对话只在进程内存、不写磁盘转录和自动记忆、Gateway 重启即消失；消息仍发给模型供应商，工具仍能写文件、碰外部服务
  - 安全：Gateway 默认绑 loopback；多数聊天渠道对陌生私信回配对码；`openclaw security audit` 查入站访问、工具半径、网络/浏览器暴露、插件白名单。文档把模型选择当作 prompt injection 的第一道缓解，同时写明面对有适应能力的人类攻击者，现有最好防御被突破的概率仍超过 80%，强制层是工具策略、执行审批和沙箱
  - 破坏性变更（二手汇总，以发布说明为准）：随包 OpenProse 插件和 `/prose` 去掉；OpenAI 路由迁到 `openai/*`。错误版本号 `2026.9.1-beta.1` 实际是 `2026.8.1-beta.4`，不要当成比稳定版 `2026.8.1` 更新
- 关键数据/指标：933 / 569 / >16000 PR、「约 50% 历史合并量」来自官方博客。575 ms / 45 个 JS 请求来自机器之心Pro 对官方模拟测试的转述。众包攻击竞技场数字（Opus 4.5 被攻破率 0.5% 等）是 2026 年另一组数据，场景定义「既执行有害操作又对用户隐瞒」才计成功
- 技术或产品细节：新装 OpenAI 配置默认 GPT-5.6；本地侧把 node-llama-cpp 换成托管 llama-server，llama.cpp 默认上下文 64K。`/btw` 开独立多轮侧边对话，避免污染主线。审批请求带 30 天历史（机器之心Pro 转述）
- 开发者可带走：自托管 Agent 网关先跑 `openclaw security audit`，不要把共享会话当成多租户。升级前备份；需要降级的人先读 SQLite 迁移说明。凭证不要进聊天记录——2.0 有 Private Credential Request，敏感输入走遮罩
- 边界与风险：新智元 9 月 1 日稿把标题写成「已无人关心」，是评论而非用量统计。项目 1–5 月有过严重 RCE / 恶意 Skill 记录，2.0 的审计命令和默认 loopback 是补课，不是「默认安全」。共享会话文档自己否认安全边界
- 为何重要：开源个人 Agent 运行时第一次把「能装起来」和「能多人接着干」写成同一版本的目标，也把降级破坏性和权限非隔离写进用户能看见的地方

### 5. Anthropic：信息窃取木马复制 Claude 登录会话，官方登出用户并删掉已存银行卡
- 类型：工程
- 来源：Help Net Security（用户通知邮件摘录）对照凤凰网科技稿；Gridinsoft 复述同一封邮件 / 2026-08-31
- 发布日期：邮件「上周」发出，英文安全媒体 2026-08-31 集中报道
- 链接：https://www.helpnetsecurity.com/2026/08/31/claude-accounts-compromised-through-infostealer/
- 阅读置信度：全文级（Help Net Security 对官方邮件的摘录）；凤凰网有黑产演绎，其「9.9 元无限畅聊」等细节未在英文稿出现，作转述保留
- 一句话：不是 Claude 服务端被攻破，是用户电脑上的通用 infostealer 把已登录的 Claude session cookie 拷走；Anthropic 撤销会话、去掉已存支付方式、退未授权扣费，并写明换密码清不掉木马。
- 中心思想：公司点名的家族包括 Windows 上的 Vidar、Lumma（LummaC2）、StealC、RedLine、Acreed，以及少量 Mac 上的 Atomic Stealer（AMOS）。邮件称这是通用木马，通常来自非官方下载或恶意应用，会静默复制浏览器密码、登录 cookie 和其他本地应用凭据；Claude 会话只是其中之一。Anthropic 写「没有理由认为木马与 Claude 有关、经 Claude 安装，或与你在 Claude 里做的事有关」；手机和平板「看起来没有卷入」。
- 关键要点：
  - 自测信号（英文稿 + 凤凰网均提到）：额度在你没用的时段被耗光，或刚恢复又被打空
  - 官方动作：登出以作废被盗会话；删除已存银行卡；退识别为未授权的 Claude 费用。再登录后需手动加回支付方式
  - 用户侧顺序（官方建议）：先杀毒清木马，再改 Claude 所用邮箱的密码并开 2FA，再轮换浏览器里保存的密码、核对卡片账单，最后才把支付方式加回 Claude
  - 凤凰网补充的变现路径（未在 Help Net Security 出现，标转述）：把会话做成套壳「低价畅聊」，或在账号里开 API Key 接到中转站按 token 卖。英文稿只写消耗订阅额度
  - 仿冒风险：安全媒体提醒会有人冒充这次通知钓鱼，不要对「官方要你提交密码/验证码」的邮件照做
- 关键数据/指标：文中未给出受影响账号数、退款总额或单账号被刷金额。木马名单来自 Anthropic 邮件
- 技术或产品细节：攻击面是浏览器会话，不是密码爆破，2FA 挡不住已窃取的 cookie。桌面 Claude / 浏览器登录都可能被收。开发者若在同一台被感染机器上存 API Key、云 AK、SSH，需要单独轮换，不能只重登 Claude
- 开发者可带走：CI 和本地 Agent 不要把 Anthropic / OpenAI token 放进浏览器能读的配置。机器中招后：杀毒 → 轮换邮箱 → 作废所有 API Key → 再加支付方式。额度莫名下降先看会话列表，不要先怪「官方偷偷扣配额」

## 给开发者的思路
1. 视觉 Agent 可以按 DeepSeek 的规则估成本：每张图最多 384 token、单请求最多 600 张，模型名 `deepseek-v4-flash-vision-exp`。截图轨迹先走 API；要自托管再下 HF 上 305B 的 MIT 权重。官方分只在 Harness minimal + `max` 档下对得上 Opus-4.8。
2. 8 月 31 日把默认模型、价格和会话安全同时改了。Sonnet 5 API 按「单价 × 新 tokenizer」重做编码账单；Codex 登录态从 GPT-5.4 迁到 Terra/Luna，要钉旧模型就改 API key 路径。Claude 额度异常先当会话被盗：杀毒、轮换 Key、再加卡，不要先怪配额政策。
3. 端侧和小开源不要等旗舰。讯飞 4B/1.7B 和 1M 上下文今天还只有短讯，先盯许可证和 RAM；OpenClaw 2.0 能装、能多人接着干，但文档写明共享会话不是租户隔离。家庭和银发硬件则对上 7 部门意见里的互联互通国标，而不是再刷一条云端榜。
