### 1. DeepSeek 正式发布并开源 V4.1 Flash：552B MoE、原生视觉、9 月 14 日起把 V4 Pro 路由到 Flash
- 类型：工程
- 来源：DeepSeek 官网《DeepSeek V4.1 Flash：更强、更快、更普惠》（2026-09-10）；对照 Hugging Face 模型卡 `deepseek-ai/DeepSeek-V4.1-Flash`；网易科技 / 网易智能（2026-09-10）
- 发布日期：2026-09-10（价格 12:00 生效；V4 Pro 路由节点为 9 月 14 日 12:00）
- 链接：https://www.deepseek.com/news/deepseek-v4-1-flash/
- 阅读置信度：全文（官网 + 模型卡）；「全面超越 V4 Pro」是官方综合口径（性能、费用、速度、总用时），模型卡分项并不处处高于 Pro
- 一句话：中间版过期后，DeepSeek 当天把 V4.1 Flash 做成正式 API 名 `deepseek-flash`，并在 Hugging Face 以 MIT 开源权重。结构是 552B MoE 的 Causal Encoder-Decoder：prefill 激活 8B、decode 激活 16B，原生图文输入、文本输出，上下文最高 1M。
- 中心思想：这不是再发一档「更快的 Flash」。官方把新结构系列的最小尺寸直接用来替换现网 Pro：9 月 14 日 12:00 之后、V4.1 Pro 上线之前，`deepseek-v4-pro` 全部打到 Flash，并按 Flash 单价计费。
- 关键要点：
  - 模型卡：40 层 Transformer，20 层因果编码器 + 20 层解码器；解码器全局 KV 由编码器末层投影，而不是每层自己产 KV。CSA2 把注意力层分成 Full / Reindex / Reuse；解码器还有 Hierarchical Sparse Indexer。主 KV 用 FP4（E2M1，每 16 通道一个 E4M3 scale），全局 KV 约 890 bytes/token，约为 V4 Flash 的 1/4
  - SWA Bounded Replay 只重放最近 `n_win` token 来重建 SWA KV，不必把 SWA KV 持久化到 SSD；官方与模型卡都写 SSD 需求约为上一代的 1/8。相对 DeepSeek V1，KV Cache 缩小约 437 倍
  - 另有 Single-Pass mHC、Engram 条件记忆（196B，按 token 稀疏查找）、DSpark 推测解码。MoE：1 个共享专家 + 每层 384 个路由专家，每 token 激活 6 个路由专家。视觉是从头训的 DeepSeek-ViT（2D-RoPE + 3×3 pixel-unshuffle），两层 MLP 投影，从预训练起就和文本一起训
  - 预训练约 45T token；稀疏注意力在 64K 上训，34T token 时把上下文扩到 1M。后训练仍是 SFT → RL → on-policy distillation，改的是数据管线（自动合成 agent 任务与环境）。`reasoning_effort` 可在整数 1–100 连续调节
  - API：改模型名为 `deepseek-flash`。`deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 已下线，旧名暂时路由到 V4.1 Flash。WorkBuddy（含 CodeBuddy）和 OpenCode 官方写已全量接入。大规模自建推理：官方欢迎「2k 卡 GPU、有存储集群」的团队联系
- 关键数据/指标：
  - Instruct（`reasoning_effort=100`，`temperature=1.0, top_p=0.95`；代码 agent 用 DeepSeek Harness Minimal + 1M 上下文）：GPQA Diamond 90.9（V4 Pro 92.4）；Terminal-Bench 2.1 90.6（Pro 87.9）；Terminal-Bench 4.0 31.2（Pro 12.4）；DeepSWE v1.1 74.2（Pro 62.7）；AutomationBench 54.8（Pro 43.2）；Agent's Last Exam 31.8（Pro 25.7）；Codeforces 评分 3471（Pro 3348）。以上均模型卡
  - 网易智能转述 API 价（2026-09-10 12:00 起，峰谷）：高峰每百万 tokens 缓存命中 0.04 元、未命中 2.0 元、输出 8.0 元；闲时 0.02 / 1.0 / 4.0 元
- 技术或产品细节：仓库不含 Jinja chat template，提示编码走 `encoding/` 参考实现或 `deepseek-recipe`。推荐 `temperature=1.0`，`top_p=0.95` 或 1.0，`context_window=1M`，`max_tokens≥256K`。HF 页显示模型体积 763B params（主干 552B + Engram 等，不要和 552B 混成同一个数）
- 开发者可带走：生产路由从今天起改 `deepseek-flash`，不要再写死 `deepseek-v4-pro`。用同一组仓库任务对 TB / DeepSWE 做回归；知识类题（GPQA、HLE）模型卡上 Flash 并不高于 Pro，不要把「全面超越」抄进选型表
- 边界与风险：官方「全面超越」是综合口径。HLE 文本子集 Flash 36.8（括号 39.1†）对 Pro 42.7†。社区「300–500 token/s」只出现在转载，不是 SLA。自建推理门槛写的是 2k 卡，不是消费级
- 为何重要：国内第一梯队把「新结构最小档」直接做成现网 Pro 的替代品，并把 KV 从 HBM/SSD 账单里砍掉一截，长会话 Agent 的成本假设要重算

### 2. OpenAI Agents API 进入公开测试：把 Codex 的托管 harness 做成 `POST /v1/agents/sessions`
- 类型：工程
- 来源：OpenAI 开发者文档 *Agents API*；OpenAI Developer Community 公告（VeitB，2026-09-10）；对照网易订阅转华尔街见闻（2026-09-11 04:01）
- 发布日期：2026-09-10（社区公告）；中文稿 9/11
- 链接：https://developers.openai.com/api/docs/guides/agents-api/overview
- 阅读置信度：全文（文档 + 社区帖）；华尔街见闻「无需额外付费」与官方「API 本身无附加费、按 token/工具/容器计费」一致，早期客户降本数字该中文稿未给可核对来源，不采用
- 一句话：OpenAI 把驱动 Codex 的云端 agent 循环（会话、编排、上下文压缩、恢复）做成公开测试 API。应用提供模型、指令、工具和执行环境；OpenAI 跑 agent loop。示例模型字符串是 `gpt-6-astra`。
- 中心思想：以前要自建 agent 循环才能接近 Codex 的长任务能力。现在循环在 OpenAI 侧，开发者选沙箱：OpenAI 托管，或自托管 / 接入 Blaxel、Cloudflare、Daytona、DigitalOcean、E2B、Modal、Oracle Cloud、Runloop、Vercel。
- 关键要点：
  - 四个概念：Agent（模型、指令、工具、MCP）、Environment（可选沙箱）、Session（可跨轮续跑的实例）、Events/Items（输入与输出）
  - harness 能力：沙箱里跑命令和代码、加载 skills、MCP 或工具连外部数据、中途 steer、摘要压缩上下文、拆子任务并委派 subagent、从中断处恢复
  - 调用：`POST https://api.openai.com/v1/agents/sessions`，请求头 `OpenAI-Beta: agents=v1`。SDK 走 `client.beta.agents.sessions.create`。文档示例开了 `programmatic_tool_calling`、MCP、`web_search`，以及 `multi_agent: { enabled: true, max_concurrent_subagents: 4 }`
  - 权限：应用 API key 需要 `api.agents.read` / `api.agents.write`，推理还要 `api.responses.write`
  - 计费：模型按所选模型 API 价；OpenAI 工具按工具价；托管沙箱按标准 container 价。社区维护者提醒：容器要先算成本再开
  - 数据控制：文档写当前数据驻留仅美国，不支持 Zero Data Retention；自托管沙箱也不能让 Agents API 变成 ZDR
- 关键数据/指标：文中未给出可核验的 QPS、默认超时或容器单价表（社区指向定价页 Containers 项，本稿未打开价目页逐行摘录）
- 技术或产品细节：环境类型文档示例有 `openai_hosted` 与 `self_hosted`（`workspace_directory`、`capability_directories`）。Quickstart 用创建 `tree.py`、跑通、读输出作为最小验收。流式结束看 `agent.session.turn.completed`；`turn.failed` / `turn.cancelled` / `session.failed` 才是失败，`agent.session.idle` 单独出现不等于成功
- 开发者可带走：已有 Codex 工作流、想嵌进自己产品的，先用托管沙箱跑 quickstart，再决定是否换 E2B / Modal / Vercel。合规上把「Agents API ≠ ZDR」写进评审表，不要假设自带沙箱就能过零留存
- 边界与风险：公开测试，接口和计费都可能改。网易稿里的「一级集成协议」「显著改善」是二手概括。Astra 在示例里出现，不代表必须用 Astra
- 为何重要：Agent 产品从「自己写 loop」变成「买 Codex 同款循环 + 自选沙箱」，和 DeepSeek 压缩 KV 是同一周的两条供给侧

### 3. GPT-Live-1 进入 API：全双工语音前端每分钟 0.05 美元，推理交给后端模型
- 类型：工程
- 来源：OpenAI《Build more natural voice experiences with GPT‑Live‑1 in the API》（2026-09-10）；对照 Developer Community 公告与 API 文档 *Managing GPT-Live sessions* / *Migrate to GPT-Live*
- 发布日期：2026-09-10
- 链接：https://openai.com/index/introducing-gpt-live-1-in-the-api/
- 阅读置信度：全文（官方页 + 社区要点 + 文档）；官方页部分评测表在抓取中不完整，数字以社区公告转述并标明
- 一句话：ChatGPT 里已经在用的全双工语音模型 GPT-Live-1 对 API 开放。它同时听和说，负责打断、语气和转写；更深的推理、工具和 agent 交给你选的后端。模型名 `gpt-live-1`。语音层 0.05 美元/分钟，按秒计费；后端模型和工具另计。
- 中心思想：这不是 Realtime 的小改版。文档把职责拆开：Live 管对话界面，后端管任务。打断用户说话，不会自动取消后端正在跑的活，权限和任务状态仍由应用控制。
- 关键要点：
  - 连接：浏览器 WebRTC，服务端 WebSocket，另有电话场景。内置转写、回复文本、keyword biasing、turn detection。音色、语速、风格用提示词调，声音选项比以前多（官方表述，未给声音列表）
  - 两种委派：托管 Responses delegation（Live 服务去调你配置的 Responses 模型），或 client delegation（接到现有 agent）。迁移指南：保留原有函数实现、鉴权和持久状态，不要把业务逻辑塞进语音层
  - 会话：创建时设定 `model` / `voice` / delegation；`instructions` 上限 16,384 tokens。历史 `input` 最多 128 条、合计 8,192 tokens，角色限 `developer` / `user` / `assistant`，不要用 `system`。换模型要新开会话
  - 录音：`store: true` 须项目允许；默认 false。录音 30 天后过期。ZDR 下 `store` 视为 false，不能下载或 fork
  - 官方举 Speak 的早期评估：相对此前轮转系统，打断减少约 80%，学习者在导师开口前有更多思考时间。这是客户评估，不是公开榜
- 关键数据/指标：语音层 0.05 美元/分钟。社区公告转述：Artificial Analysis Conversational Dynamics 97.3%；Full Duplex Bench v1.5 interactivity 80.1%；响应时延 0.798 秒，对照 GPT-Realtime-2.1 的 1.41 秒；Full Duplex Bench v3 在后端管工具时 tool-calling 成功率 87%、response quality 90%。后一组数字未在本稿打开的官方 HTML 全文里逐行核对
- 技术或产品细节：OpenAI Presence 可用同一模型做客服类实时语音，走客户经理，不是自助 API 开关
- 开发者可带走：现有 Realtime 或「ASR+LLM+TTS」链，按迁移文档把提示词拆成「怎么说话」和「怎么办事」两套。计费按「分钟语音 + 后端 token」分开估，不要只看 0.05 美元
- 边界与风险：打断不取消后端，产品上要自己做取消/确认。评测分数部分来自社区转述。电话场景的运营商细节文档未在本条展开
- 为何重要：语音 Agent 的接口从「一个模型包办听想说」变成「前端全双工 + 后端任意 harness」，可以和 Astra / Agents API / 自建循环组合

### 4. Cognition：研究员用多路 Devin 实现 GPU 格筛，分解 RSA-260，公开纪录时隔六年半被刷新
- 类型：工程
- 来源：Cognition 博客 Eric Lu《Factoring RSA-260》（2026-09-09）
- 发布日期：2026-09-09
- 链接：https://cognition.com/blog/factoring-rsa-260
- 阅读置信度：全文（官方博客）；成本、RSA-1024 外推是作者估算，第三方尚未复现整次计算
- 一句话：Cognition 研究员 Eric Lu 把一群 Devin 对准 CADO-NFS，写出 GPU 格筛 `glas`，用 GNFS 分解了 260 位十进制的 RSA-260。这是 RSA Factoring Challenge 目前公开解出的最大一题。上一档 RSA-250 停在 2020 年 2 月。
- 中心思想：作者写「几乎没有算法创新」，快在把格筛和稀疏线性代数搬上 GPU 内存带宽。人的工作是定优先级、建基准、发现跑偏；测量、集群操作和端到端优化由 Devin 做。作者认为这替代了领域专家团队数月的活。
- 关键要点：
  - 分解式（博客原文，可用两素数相乘核对）：
    `22112825529529666435281085255026230927612089502470015394413748319128822941402001986512729726569746599085900330031400051170742204560859276357953757185954298838958709229238491006703034124620545784566413664540684214361293017694020846391065875914794251435144458199`
    `= 4397328654844826923795068102505872571721883526553349659561256924505973939597593482272505698004801207988043088656411102133523080581`
    `× 5028695206842569864686141618253083416610081090075366674776775706538324961364412200138116378509733307971876652984898985905923678379`
  - 作者强调：不是手猜 130 位素数，也没有量子计算机。实现基于大幅改过的 CADO-NFS
  - 成本：约 4,900 GPU-日（13.5 GPU-年），按当时 GPU 市价约 40 万美元。分段：多项式选择 643 GPU-日（作者称因操作失误偏高）、筛法 3,813、线性代数 467（其中约 7% 因崩溃或被抢占无效）。跑在训练/推理集群里用不满的边角算力（NVL72 机架装箱后的空节点），边际成本按作者说法接近零
  - 工作方式：2026-08-13 把 Devin 指向替换 CADO 的 CPU 筛 `las`；两小时后要求能跑 RSA-250 参数。作者睡一觉，约 7 小时迭代后 Devin 给出可工作的 GPU 筛。三周里平均 3 路、最多 18 路并发 Devin。前五天把分解 190 位数的墙钟做到接近刚开始分解 157 位数的水平
  - 安全外推（作者）：按 GNFS 标度，RSA-1024（约 309 位）大约是 RSA-260 的 78 倍计算量，市价估约 3000 万美元，再优化「很可能再降一倍」；RSA-2048 仍大约难 10 亿倍，「看起来没有被这次工作实质改变」。1024 位 RSA 2013 年已弃用；现网常用 2048 位（约 617 位）
- 关键数据/指标：4,900 GPU-日 / 约 40 万美元 / 筛法产出约 83 亿条 GF(2) 关系。10× 低于「此前公开 SOTA 成本」是作者对比，不是第三方审计
- 技术或产品细节：改动覆盖 GPU 版 stage-1 polyselect、格筛、CADO 调度头、dup/purge、merge/replay、GPU block Wiedemann、GPU sqrt。未动的包括 `cado-nfs.py`、`polyselect_ropt`、`makefb`、`dup1`。博客未承诺开源 `glas`
- 开发者可带走：因子本身可本地相乘验证；成本账和 10×、3000 万美元外推不能当密码学评估输入。真正能用的是「边角 GPU + 可抢占、细粒度并行」这类调度模式。不要把标题读成「AI 破解了银行 RSA」
- 边界与风险：单方数据，筛参数未经 2020 年那种多团队交叉验证。GPU 型号、失败任务是否计入、市价口径未拆开。Scientific American 9 月 4 日那篇还处在作者开玩笑「纸笔分解」的阶段，以 9 月 9 日这篇技术博文为准
- 为何重要：编码 Agent 第一次把公开 RSA 纪录往前推了一档，同时把「非密码学家也能做大规模科学计算」写进了公司博客

### 5. 蚂蚁灵波开源 LingBot-World 2.0：1.3B 消费级单卡档，并放出双向 Teacher 与因果预训练基座
- 类型：工程
- 来源：微信公号「机器人前瞻」（钟宸，凤凰网科技转载，2026-09-10）；对照项目页 `technology.robbyant.com/lingbot-world-v2` 与 Hugging Face `robbyant/lingbot-world-v2`
- 发布日期：2026-09-10（稿件写 X 上为前一晚官宣）
- 链接：https://tech.ifeng.com/c/8wJH4iv5mK2
- 阅读置信度：全文（公号转载）；项目页另有 LingBot-World-Infinity 的 720p / 60fps 宣传，与本次开源的 1.3B 不是同一套数字，不混写
- 一句话：蚂蚁集团具身公司灵波（Robbyant）开源三件：LingBot-World 2.0 Small（1.3B，面向消费级单卡实时生成）、Bidirectional（双向 Teacher，给蒸馏用）、Causal Pretrain（因果预训练基座，给后训练和评测用）。魔搭与 Hugging Face 已上线。
- 中心思想：公号认为看点不是又一段可玩视频，而是参数从既有 14B 档收到 1.3B 的同时，把蒸馏 Teacher 和预训练基座一起交出来，社区可以跳过从零预训练。
- 关键要点：
  - Small：官方称单卡实时；个人开发者、高校实验室、小团队可本地复现
  - Bidirectional：实时世界模型训练里，Teacher 多步去噪贵，难以直接交互；蒸馏把多步轨迹压到少步 Student。开放 Teacher 是为了让别人训更轻、更快或垂直场景的 Student
  - Causal Pretrain：后训练、评测、场景适配的底座。不做预训练也可以只在该基座上后训练
  - 稿件描述的生成内容：可控人物行走/滑翔、喷水/彩虹/闪电/巨浪等天气、不同人称、射击与换弹。作者同时写：夸张度较大，真实性不足
  - 项目页上的 Infinity：开放世界、长时间视觉一致、720p 60fps、亚秒级控制延迟、多人一导一玩。权重「将发布」。这些是产品页句子，不是 1.3B 的实测
- 关键数据/指标：1.3B；对照 14B 来自该公号。项目页的 720p / 60fps / 亚秒延迟未给出对应权重档和测试卡型

### 6. 腾讯混元开源 AuK：1.5B 语音生成与编辑统一入口，蒸馏版 AuK-Flash 四步、官方称 4.5 倍墙钟加速
- 类型：工程
- 来源：arXiv:2609.08936 *AuK Technical Report*（HF Papers 页摘要，2026-09-08/09）；对照 Cocoloop 2026-09-10 对 GitHub `Tencent-Hunyuan/AuK` 的核验稿
- 发布日期：论文页 9/8–9/9；中文整理 9/10
- 链接：https://github.com/Tencent-Hunyuan/AuK

- 一句话：混元把 TTS、内容改写、音高语速、情绪/音色/口音、降噪去混响、分离收进同一个「自然语言指令 + 参考音频」接口。权重和代码 MIT 开源，HF 与魔搭同步。
- 中心思想：差异点在编辑，不只是生成。已有音频改完还要保住原说话人，和「给定文本出声音」不是同一类工程问题。

  - 结构：多模态 LLM 做语义条件；在语音、通用音频和音乐上联合训的 VAE 做声学条件；hybrid rectified-flow Transformer（先双流 MMDiT，再单流 DiT）。训练先 generation-only warmup，再联合生成–编辑预训练；后训练用人类反馈偏好优化开放编辑，用奖励 RL 做语音生成
  - AuK-Flash：consistency 初始化 + 按任务路由的 Decoupled DMD；4 步推理、不开 CFG；官方/论文：相对全量模型 4.5 倍墙钟加速（matched conditions）。核验稿写编码器底座是 Qwen2.5-Omni-3B
  - 仓库带 Python API、Gradio、ComfyUI 节点。演示为中英文
- 关键数据/指标：1.5B；3.03B 条 / 195 万小时；4 步；4.5×。WER、说话人相似度、MOS 未在摘要给出可摘数字
- 技术或产品细节：代码 GitHub Tencent-Hunyuan/AuK。许可 MIT。Cocoloop 写「超过 15 项任务」，与论文五类任务是不同粒度
- 开发者可带走：后期制作链路若现在是 TTS + 变声 + 分离三套模型，先用 Gradio 把「改词但保住音色」跑通，再看 Flash 的 4 步能不能进延迟预算。许可证按 MIT 评估商用，不要默认还有国内自定义条款
- 边界与风险：摘要称 generation 与 instruction-guided editing「leading」，信号级修复只写 competitive。客观损失未随 4.5× 一起公布。参数量 1.5B 与条件编码器 3B 如何拼装，以仓库配置为准
- 为何重要：开源语音从「再做一个 TTS」转到「一条指令改已有声音」，和 GPT-Live-1 的实时对话前端不在同一层
