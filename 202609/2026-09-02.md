- 一句话：同一底座两套护栏：Fable 5.1 全面开放，Mythos 5.1 只给可信访问计划；官方 8 项表上 Fable 5.1 均高于 Fable 5 / Opus 5 / GPT-5.6 Sol，Terminal-Bench-Science 0.1 从 24.7% 到 52.6%；标价不动，缓存读取从每百万 $1 降到 $0.25。

- 关键要点：
  - 官方评测表（生产护栏开启）：Terminal-Bench-Science 0.1 为 52.6%（Fable 5 24.7%、Opus 5 29.0%、GPT-5.6 Sol 22.4%）；Terminal-Bench 4.0 为 55.8%，Mythos 5.1 为 60.9%（Fable 5 42.0%、Opus 5 52.3%、Sol 37.3%）；CursorBench 3.2.0 为 73.4%（Fable 5 70.5%、Opus 5 70.0%、Sol 67.2%）；AutomationBench 31.4%（Fable 5 17.1%、Opus 5 26.9%）；OSWorld 2.0 部分 77.9% / 严格 41.7%；HLE 无工具 60.9%、有工具 65.0%；GDPval-AA v2 为 1853

- 关键数据/指标：上表数字均为 Anthropic 官方评测。Millennium 称内部百万分之一崩溃排查数年未果，Fable 5.1 反汇编外部库并对上 core dump。Cognition 称上线日把 Devin 里的 Opus 5 流量迁到 Fable 5.1。Artificial Analysis 指数 66 分（智东西转述，对 Opus 5 的 63、Fable 5 的 62、Sol / Grok 4.6 的 61）

- 关键数据/指标：ExploitBench 满分、两个未知零日来自观察者网对 OpenAI 的转述，待与系统卡核对。Jailbreak 拒绝率 91.5%、相对前代 59% 等数字出现在第三方解读稿，本条未打开官方系统卡，不收录

### 3. 科大讯飞词元星火正式开源 Spark-X2.5-4B / 1.7B：原生 1M 上下文，Apache 2.0
- 类型：工程
- 来源：Hugging Face 模型卡 XHToken/Spark-X2.5-4B + IT之家 / 2026-09-01；新京报贝壳财经对照
- 发布日期：2026-09-01

- 阅读置信度：全文（模型卡）；IT之家 / 贝壳财经为产品说明对照。昨日日报是预告短讯，本条按已上线权重重写
- 一句话：两款端侧通用模型以 Apache 2.0 放出 Transformers 权重，混合注意力（1 层全注意力 + 3 层滑动窗口）原生到 1,048,576 token；预训练约 20 万亿 token，在昇腾集群上训练。
- 中心思想：模型卡把目标写成「同尺寸开源里把 Agent / 代码 / 推理 / 指令遵循做上去」，并给出与 Qwen3.5-9B/4B/2B、Gemma4-12B/E4B/E2B 的官方对照表。评测全部在 thinking 模式，推荐 `temperature=1.0, top_p=0.95, top_k=-1`。
- 关键要点：
  - 架构：滑动窗口 + 混合全注意力，用来压长上下文 KV。支持 200 种以上语言。后训练：SFT 后按语言理解、推理、编程、工具 Agent、指令遵循分别做大规模 RL，再用 MOPD 把多教师策略合成一个可部署模型
  - 官方表（4B / 1.7B vs Qwen3.5-4B）：SWE-Bench Pro 44.4 / 10.4 vs 29.4*；SWE-Bench Verified 41.6 / 28.3 vs 38.8*；MCP-Atlas 54.6 / 23.4 vs 40.8*；BrowseComp 40.9 / 29.7 vs 14.3；τ³-bench 30.4 / 20.1 vs 6.7；AIME 2026 90.7 / 69.4 vs 83.0；高考 2026（五套卷、每套 150 分）133.4 / 114.8 vs 130.3。带 * 的对比分来自对方模型卡，不是讯飞复测
  - 部署：NVIDIA / 昇腾 / 海光 / 后摩；vLLM、SGLang、llama.cpp、MLX；Ollama / LM Studio；微调走 LLaMA-Factory。SGLang 示例把 `--context-length` 设到 1048576，显存不够需自行下调。工具解析器 `spark25`，reasoning 解析器 `qwen3`
  - IT之家：讯飞星辰 MaaS API 限时免费；Domux 智能家居测试集上 1.7B 控制指令端到端正确率 90.3%、平均响应 0.85 秒（公司场景数字，模型卡未列）。9 月 7 日再发星火 X2.5-293B 基座
- 关键数据/指标：4B / 1.7B 参数、20T 预训练、1M 上下文、Apache 2.0 来自模型卡。Safetensors 页写 Model size 4B params、BF16。Domux 90.3% / 0.85s 来自 IT之家对公司介绍的转述
- 技术或产品细节：HF 集合 https://huggingface.co/collections/XHToken/spark-x25 ；GitHub https://github.com/XHToken/Spark-X2.5 。Ollama / LM Studio 需用讯飞 fork 的 llama.cpp，不是上游默认二进制。昇腾走官方 vLLM-Ascend / SGLang 镜像后再装 Spark-plugin
- 开发者可带走：端侧先拉 4B 在 thinking 模式下用同一套采样参数复测自己的仓库任务，不要直接引用带 * 的跨模型卡数字。1M 上下文是 native 训练到的，但推理时 `--context-length` 和显存是两件事。许可证是 Apache 2.0，比昨日短讯里的「待核实」已落地
- 边界与风险：「端侧唯一百万上下文」是 IT之家对公司表述的转述，未做全市场普查。官方表是同尺寸开源对比，不是对标 Fable / Opus。293B 是否开源仍待 9 月 7 日。MaaS「限时免费」无截止日期
- 为何重要：昨天还只是排期，今天有权重、许可证、混合注意力说明和可复现的 serving 命令

### 4. 腾讯混元把 Hy4 preview 压到约 214GB：Sherry 三值量化 + 异构联合推理
- 类型：工程
- 来源：IT之家对腾讯混元 9 月 1 日公告的报道；权重页 AngelSlim/Hy4-preview-GGUF、tencent/Hy4-preview、github.com/Tencent/AngelSlim
- 发布日期：2026-09-01
- 链接：https://www.ithome.com/0/996/880.htm
- 阅读置信度：全文（IT之家）；量化论文/技术报告未打开，比特数与榜分以该稿对官方说明的转述为准
- 一句话：8 月 28 日开源的 770B-A49B Hy4 preview，BF16 权重接近 1.5TB，轻量版压到约 214GB；在 4090 笔记本 + 四卡 A4000、分属两个局域网的条件下，prima.cpp 把 MoE 层拆开跑到 1.02 token/s。
- 中心思想：这是部署压缩，不是新基座。IT之家写两项技术：Sherry 稀疏三值量化，路由专家层平均 1.25 bit；MIX-STQ1_0 按校准数据逐层选位宽，敏感层 2.06 bit（IQ2_XXS），不敏感层 STQ1_0 的 1.31 bit。
- 关键要点：
  - 能力口径（公司）：长文理解几乎与 BF16 持平；多轮长上下文检索基本同一水平；数学小幅回落。MCP Atlas 83.7→83.2；SWE-Bench multi 82.9→81.3
  - 异构演示：单 4090 笔记本 + 四卡 A4000 服务器，合计 80GB 显存、64GB 内存。比笔记本单机 offload 快约 6 倍。1.02 token/s 是这一套硬件上的演示速度，不是数据中心吞吐
  - 已上线 llama.cpp / vLLM / SGLang。GGUF 在 `AngelSlim/Hy4-preview-GGUF`，压缩代码在 `Tencent/AngelSlim`
- 关键数据/指标：1.5TB→214GB、1.25 / 2.06 / 1.31 bit、1.02 token/s、约 6×，均来自 IT之家对混元说明的转述。原模型规格 770B-A49B、1M 上下文见 8 月 29 日日报，本条不重复内部盲测
- 技术或产品细节：Sherry 与 MIX-STQ1_0 的实现细节、校准集、哪些层被标为敏感，IT之家未展开。跨局域网联合推理依赖 prima.cpp 的 MoE 调度，不是 vLLM 默认张量并行
- 开发者可带走：要本地碰 Hy4，先下 214GB GGUF，不要按 1.5TB BF16 估磁盘。1.02 token/s 只证明「能跑起来」，编码 Agent 交互仍偏慢，适合批处理和长文档，不适合当默认补全引擎
- 边界与风险：MCP Atlas / SWE-Bench multi 的对比条件（是否同一 harness、是否 thinking）原文没写。214GB 对消费级单机仍大。Hy4 仍是 preview，正式旗舰未定
- 为何重要：开源 770B MoE 的卡点从「有没有权重」变成「磁盘和跨机调度」；量化配方和联合推理脚本一起给了

- 类型：产品
- 来源：Runway 官方《Introducing Solaris》/ 2026-08-31；arXiv:2609.00776 同期

- 中心思想：现有软件要把视觉设计翻译成代码，再损失一层交互可能性。Solaris 把渲染和响应绑在同一个世界模型里。语言模特负责「下一步该发生什么」，世界模型负责「这一帧长什么样」。底座是改编过的 Gen-4.5，再接 GWM-1 路线。
- 关键要点：
  - 实时化三步：先改成自回归按帧生成；再把多步去噪蒸馏成很少几步；最后用自身输出训练，让长交互质量稳住。工程目标：实时交互、整段会话连贯、720p
  - 人评：250 人、30 个交互例、近 7500 对比较。对同一张起始图、同一条交互指令，Solaris vs 用 Claude Opus 5 写出的编码界面：指令遵循 61% vs 24%（13% 相当）；场景内自然程度 71% vs 21%（6% 相当）
  - 信息损失实验：让包括 Claude Fable 5 在内的多模态语言模型根据截图重建 30 个界面，SSIM + DINOv3 均显示复杂度上升则保真度下降；Solaris 的论点是根本不经过语言中间层
  - 明确做不到：稳定可读文字；长时间会话的视觉/语义连贯；无 DOM 导致读屏等无障碍接口没有挂载点；教学/电商场景下「看起来很真的错误答案」
- 关键数据/指标：250 / 30 / ~7500、61%/24%、71%/21% 为官方用户研究。延迟「大约半秒以上就不像交互」是工程判断，官方未公布实测毫秒数。CMSWire 等二手写「低于 500ms」，博文正文没有这个数
- 技术或产品细节：用户给起始状态（品牌环境或产品场景），模型实时出帧。交互含义用文本提示指定，而不是写事件处理函数。早期访问表；无 API 名、无价格、无 GA。2 月 Series E 3.15 亿美元、估值约 53 亿美元是既有融资背景，不是本条新数字
- 开发者可带走：这是研究预览，不能替换生产前端。若做 Agent 电脑操作，可以把「布局稍变任务就失败」当成训练动机来看，但今天没有可调的 endpoint。无障碍不合规是硬限制，不是小问题
- 边界与风险：人评是「看起来自然」，不是任务完成率、支付正确率或 WCAG。截图重建实验证明语言模型会丢信息，并不证明 Solaris 在真实业务系统里可靠。文字生成仍是视频模型老问题
- 为何重要：世界模型被用来当操作系统图层，而不只是出片工具；和同日 Atlas 的空间世界模型是两条产品线

## 给开发者的思路
1. 编码 Agent 的默认模型这周要改成可切换配置。Fable 5.1 用 `claude-fable-5-1`，先开 cache、按 Medium/Low 对成本，High 留给 Claude Code 里确实跑不完的任务；渗透测试和写 exploit 会被踢到 Opus。千问侧把 `qwen3.8-max-0902` 当作免费升级，仓库问答可以切，长程补全仍用自己的失败率而不是官方 TerminalBench。Astra 没有公开 endpoint，不要写进 9 月排期。
2. 端侧和本地：讯飞 4B Apache 2.0 已经可下，serving 用官方 SGLang/vLLM 命令，1M 是训练窗口不是你那张卡的显存。Hy4 先下 214GB GGUF，1.02 token/s 的异构演示只能证明能跑，不能当 IDE 补全。Flash 价带（投中网汇总的 0.8 元档）适合短循环工具调用，旗舰留给重试。
3. 世界模型和联络 Agent 都还不能当操作系统。Atlas / Solaris 是早期访问和研究预览，无障碍、文字、定价都没给。若要可核算产出，百融把指标定在转人工率和有效通话上，比再接一个生成式 UI 更接近能签的合同。
