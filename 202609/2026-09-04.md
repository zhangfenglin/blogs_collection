### 1. OpenAI 正式发布 GPT-6 Astra：API 短上下文 $10 / $50，先给受信访问再推付费档
- 类型：工程
- 来源：OpenAI ChatGPT Release Notes（2026-09-03）+ API 价目页；对照 The New Stack《OpenAI launches GPT-6 Astra…》、The Verge、网易智能 / 2026-09-04、极客公园（网易号）
- 发布日期：2026-09-03（美东）；中文 2026-09-04
- 链接：https://help.openai.com/en/articles/6825453-chatgpt-release-notes
- 阅读置信度：全文（帮助中心、价目页、TNS、Verge、网易智能、极客公园）。OpenAI 营销主页本次抓取超时，系统卡未逐段打开
- 一句话：旗舰从 GPT-5.6 换成 GPT-6 Astra；ChatGPT 帮助中心写「尚非普遍可用，未来数日扩大」；API 短上下文每百万 token 输入 $10、缓存命中 $1、缓存写入 $12.50、输出 $50，长上下文翻到 $20 / $2 / $25 / $75。
- 中心思想：OpenAI 把它写成「迄今最智能、最对齐」的模型，总裁 Greg Brockman 在发布会收尾说「Welcome to the AGI era」，同时承认 AGI 仍是「灰色、模糊」的概念，并说这不再绑 Microsoft 合同触发条件。TNS 写明：被问是否正式宣布已实现 AGI 时，他说留给读者判断，「就我个人而言，我认为我们到了」。
- 关键要点：
  - 推送：帮助中心写先给有限机构；TNS / Verge 写今日先给已有 Daybreak 的企业网络安全客户，随后数日到 Plus / Pro / Business / Enterprise，以及 OpenAI API 和 AWS。极客公园还写 Microsoft Azure。企业工作区需管理员开启、发布初期默认关闭（DeepTech 深科技转述，待与管理文档核对）
  - 型号：TNS 称目前只有 Astra 与 Astra Pro，没有 GPT-6 的 Luna / Terra / Sol 三档。价目页模型名为 `gpt-6-astra`。Trusted Access Program 企业今天可走 API
  - 训练：TNS 引研究训练副总裁 Aidan Clark：德州 Stargate 首次用超过 10 万块 GPU 做预训练；也是「前代模型在监督训练过程中起重要作用」的第一次发布
  - 价格对照（TNS）：Astra 短上下文是 GPT-5.6 Sol 当前促销价（$4 / $20）的 2.5 倍，与 Anthropic Fable 5.1 标价相同；Muse Spark 1.3 标准档 $1.25 / $4.25；Gemini 3.8 Flash 引导价 $0.75 / $3.75。Brockman：「该看的是每项任务的价格」
  - 网易智能摘 Artificial Analysis：Intelligence Index 上 Astra 约 61 分，与 GPT-5.6 Sol 接近，低于 Fable 5.1 约 66 分；Coding Agent Index 上经 Codex 得 67 分，单任务成本不到 Fable 5 的一半。该站称最高努力档 token 比 Sol 少约 10%，但单价上涨使单任务成本约高 75%。OpenAI 用 DeepSWE 称最高分配置下单任务预估 API 成本比 Sol 低约 57%——两套任务集，不是同一句话
- 关键数据/指标：价目来自 developers.openai.com。10 万 GPU、Astra/Astra Pro 来自 TNS 对发布会的报道。AA 分数为网易智能转述，接入前以该站当日页为准
- 技术或产品细节：ChatGPT 订阅用户的用量计入现有额度（极客公园）。符合条件的 API 客户可用零留存（TNS）。区域数据处理端点对 2026-03-05 及以后符合条件的型号加价 10%（价目页）
- 开发者可带走：今天不要把 `gpt-6-astra` 写成已全量。先核对自己组织是否在 Trusted Access；账单模型按短/长上下文两套价，缓存命中是 $1 不是 $10。和 Fable 5.1、Muse 1.3 比成本，用同一组仓库任务，不要只用标价倍数
- 边界与风险：「AGI 时代」是 Brockman 个人判断，不是公司合同定义。系统卡本次未全文核对。TNS 股东 Insight Partners 是 OpenAI 投资方，文末有披露
- 为何重要：昨日日报还是 Critical 门槛与「API 会被掐断」；今天有模型名、价目和分批推送，编码 Agent 的默认旗舰候选从「等 Astra」变成「能叫到再测」

### 2. Astra 的产品形态：看屏幕操作软件，Codex 可跨上下文窗口记笔记
- 类型：工程
- 来源：The New Stack 发布稿；对照极客公园、网易智能
- 发布日期：2026-09-03
- 链接：https://thenewstack.io/openai-gpt6-astra-benchmarks/
- 阅读置信度：全文（TNS）；演示耗时是 OpenAI 内部案例，不是第三方盲测
- 一句话：官方 slogan（极客公园摘）是「Anything you can do on a computer, Astra can do for you」；路径是像素 + 键鼠，而不是等每个软件先写 API。Codex 侧实验功能：任务超出窗口后可保留笔记并检索更早的消息和工具输出。
- 中心思想：TNS 认为对开发者更要紧的，往往不是榜上多几个点，而是长任务不再只靠 compaction（摘要挤窗口、可能丢掉「上次为什么失败」）。笔记功能目前藏在 `config.toml`，OpenAI 称数周内会成为 Astra 默认。
- 关键要点：
  - 计算机使用：演示含 KiCad、Excel、Blender、Power BI、浏览器填表和网站 QA。极客公园：一张原理图在 KiCad 里布局走线用时 2 分 54 秒；Blender 建房再导入 Unreal Engine 5。网易智能：Cognition 发布日把 Astra 接进 Devin
  - OSWorld V2-Offline（TNS，部分评分）：Astra 72.6%，GPT-5.6 Sol 65.7%；平均每任务约 40 分钟，Sol 约 75 分钟。Anthropic 报 Fable 5.1 为 77.9%，但用了不同 OSWorld 版本，官方自己写不可与既有分数直接比
  - 新 Codex harness：Mind2Web 上 Astra + 新 harness 完成任务比当前 Sol 方案快 1.9 倍。Astra 可以在不等待某个问题答案的情况下继续做不依赖该答案的工作
  - 内部计时（极客公园，公司演示）：「找猫咪临时看护」5 分 27 秒，人类对照 30 分钟；「求职准备」2 分 51 秒，人类对照 5 小时——未说明样本量和是否含人工接管
  - 网易智能：Agents' Last Exam 上 Astra 59.3%，高于 Opus 5 的 55.5% 和 Sol 的 53.6%；最高分配置下输出 token 比 Opus 5 少约 65%
- 关键数据/指标：72.6% / 40 分钟 / 1.9 倍来自 TNS 对 OpenAI 的摘录。2:54、5:27、2:51 来自极客公园对官方演示的转述
- 技术或产品细节：笔记与跨窗口检索是实验开关，不是今天所有 Codex 会话的默认。公开版会拒绝部分高级网络安全工作（含 exploit 发现）；Daybreak Blue 给受审防御者较松的权限。标准 API 上网络安全安全检查会直接停任务，而不是暂停等人批
- 开发者可带走：长会话先打开笔记开关做对照，看「需求被摘要掉」是否减少。Computer Use 评测用离线 OSWorld 的部分分，不要写成「72.6% 的真实企业流程已经能做完」。安全向工作走 Daybreak，不要用普通 `gpt-6-astra` 做 exploit
- 边界与风险：Matt Shumer 虚幻引擎「Agent 互相说话」是个人预览，网易智能已标明不能外推。Mia Glaese 警告：受信计划外的用户做网络安全——有时做无关工作时——可能遇到变慢、暂停或阻断，「上线时大家就该预期到」
- 为何重要：编码 Agent 的瓶颈从「窗口摘要丢细节」转到「模型自己检索旧轨迹」；这会改 harness，而不只是换模型字符串

### 3. ARC-AGI-3 报 98.6%：分数测的是 Astra + Responses API harness，不是裸模型
- 类型：工程
- 来源：The New Stack《GPT-6 Astra aced the hardest AI benchmark. The asterisk matters more than the score.》对照 TNS 发布稿、网易智能、极客公园
- 发布日期：2026-09-03
- 链接：https://thenewstack.io/astra-arc-agi-benchmark/
- 阅读置信度：全文（TNS 两篇）。ARC-AGI-3 公开集与私有集、有状态 / 无状态的完整表，本次未打开 Epoch / ARC 官方榜
- 一句话：OpenAI 报 Astra 在 ARC-AGI-3 上 98.6%（TNS），对照该公司给 GPT-5.6 Sol 的 7.8%；评测开了 Responses API 的 retained reasoning 和 compaction。网易智能写成 99.9%，与 TNS / 极客公园的 98.6% 不一致，本条以 TNS 为准。
- 中心思想：OpenAI 自己以前写过：只改这两个 API 设定，就可以在不换模型的情况下把 ARC-AGI-3 公开集分数乘大约 3、输出 token 减大约 6。因此 98.6% 衡量的是「模型 + 代理系统」，横向对比时其他模型若没用同一套 harness，不能当裸能力排名。
- 关键要点：
  - TNS 发布稿：Astra 最大努力档。DeepSWE v1.1（113 题）74.1%，Sol 70.8%；Meta 本周报 Muse Spark 1.3 最大推理档 75.4%，但该档仍在安全审查、发布时不普遍可用。公开 DeepSWE 榜上 Gemini 3.8 Flash 与 Opus 5 为 74%、Sol 为 73%，不确定区间重叠。OpenAI 图里 Fable 5.1 写成 67.4%，并去掉了 Muse
  - FrontierMath Tier 4：97.6%。TNS 称这像是覆盖 43 题里 41 道私有题；Epoch AI 说 OpenAI 资助了该基准并独占一部分，阅读时要带上这层
  - Terminal-Bench Science：Astra 64.6%，Fable 5.1 官方 52.6%，公开榜 Opus 5 约 30%。极客公园：Humanity's Last Exam（含工具）Astra 57.2%，Fable 5.1 为 65.0%——不是全面第一
  - BenchCAD Vision2Code 1000 文件子集（Python 工具）：Astra 95.9%，Fable 5.1 84.3%，Sol 83.3%。OpenAI 注明 Claude 侧用了改过的评测设定
  - 网易智能：Terminal-Bench 4.0 上 Astra 57.9%、Sol 37.3%、Fable 5.1 55.8%；GPQA Diamond 96.0%；ExploitBench 100%（Sol 78.5%）；SRE-Bench 单次 88.0%、四次内 99.2%（上一代 55.9% / 68.7%）。成绩单未给 GDPval
  - 数学研究（TNS）：公司称 Astra 参与了两则素数间隔新结果；其中一则在 Julia Stadlmann 把有界间隔从 246 收到 240 之后，再收到 186。TNS 写明：没写清哪些是模型独立提出、哪些是研究者提示
- 关键数据/指标：98.6% / 74.1% / 64.6% / 97.6% 来自 TNS 对 OpenAI 发布材料的摘录。99.9% 只出现在网易智能，本条不采用。GDPval 缺席是网易智能的观察
- 技术或产品细节：开发者若要对齐官方 ARC 数字，应用 Responses API 而不是 Chat Completions，并打开 retained reasoning 与 compaction。无状态普通调用分数会明显更低（极客公园）
- 开发者可带走：评测脚本写上 harness 名称。DeepSWE 上 Astra、Gemini 3.8 Flash、Opus 5、Muse 1.3（max）挤在同一两个点里，选模仍看自己的仓库和单价。GDPval 没出，不要用「知识工作全面超越」做对外材料
- 边界与风险：最大努力档会拉高延迟和 token。FrontierMath 存在资助方与独占题。ARC 高分不能单独支撑 AGI 声明。Epoch 的 Greg Burnham 对 TNS 的评论是「一个时代的结束、另一个的开始」，不是官方定义
- 为何重要：旗舰发布的分数已经明确依赖代理层；昨天 Gemini 3.8 的表没含 Fable 5.1，今天 OpenAI 的图没含 Muse——对照集要自己拼

### 4. 新智元（发布前）：Astra 被指用「循环深度 / 循环 Transformer」，思考过程更难看
- 类型：工程
- 来源：微信公号「新智元」（ID：AI_era）经 36 氪授权转载 / 2026-09-03 12:14；对照 The Information 原文未打开。发布后的 TNS / 系统卡转述作对照，不把架构写成官方已确认
- 发布日期：2026-09-03（Astra 上线前数小时）
- 链接：https://www.36kr.com/p/3967133839498752
- 阅读置信度：摘要级（公号对 The Information 的转述 + 学界论文背景；OpenAI 9/3 发布材料未写「Looped Transformer」这一名称）
- 一句话：发布前稿称 Astra 用 recurrent depth（又称 Looped Transformer）：同一组层循环多圈再出 token，书面思维链变短，内部计算加长。首席科学家 Jakub Pachocki 回应：内部最前沿模型（含 Astra）的计算图深度最多约是 GPT-4 的两倍，没有外界传的那么夸张。
- 中心思想：新智元把这写成「测试时算力」的另一条轴：以前「多想」= 多写 CoT token；现在一部分串行计算可以发生在出字之前。代价是监督者更难从文字里看到模型在想什么。这与发布后 TNS / 网易智能写的「书面推理更难监控」方向一致，但「循环 Transformer 就是 Astra 的主干」仍是报道，不是官方架构白皮书。
- 关键要点：
  - 稿件引用谷歌 2025 年论文 *Reasoning with Latent Thoughts*：k 层循环 L 次，在不少推理任务上可接近 k×L 层普通模型。另引今年 2 月潜在推理研究：3.5B 小模型把核心块循环足够多次，成绩可到约 50B 量级——这是论文结果，不是 Astra 规格
  - 对照 Meta Coconut（连续思维链）：向量空间推理可能比强迫每步译成人话更准、更省，也更不透明
  - 发布后对照：OpenAI 把可监控性下降部分归因于「简单任务少写推理步骤」。Redwood Research 的 Ryan Greenblatt（网易智能引）观察到 Astra 能在不写完整推理的情况下解竞赛数学。Pachocki：「智能的进步并不能保证对齐的进步」；监控信心不够就会停 scaling
  - 新智元还写「可持续数周的持续性智能体」、Altman 称计算机使用「媲美人类」——发布前措辞，发布材料改成了 OSWorld 72.6% 等可核验分数
- 关键数据/指标：计算图「最多约 GPT-4 的两倍」为 Pachocki 回应，经新智元转述。Astra 层数、循环次数、参数量，官方发布未给
- 技术或产品细节：没有可调用的架构开关或论文与 Astra 的一一映射。开发者能碰到的，是更短的书面 reasoning 和更难做 CoT 监控，而不是一个名叫 looped-transformer 的 API 参数
- 开发者可带走：不要把「循环 Transformer」写进架构评审当既成事实。安全评审按「书面 CoT 可能变短、分类器要看行动」来设计，和昨日「API 任务会被停」是同一条链
- 边界与风险：The Information 原文本次未打开。新智元有「全网恐慌」「直线拉爆」等公号修辞，本条只保留可核对的机制描述。发布材料未确认该架构名称
- 为何重要：如果内部循环成为旗舰标配，思维链监控会从「读字」变成「读行动与分类器」，这会改 agent 的审计日志设计

- 关键数据/指标：0% / 48.2%、42.4% / 30.3%、ExploitBench 100% 来自 TNS 对 OpenAI 的摘录。两个未知 V8 漏洞是公司评测声明，无 CVE 编号
- 技术或产品细节：生产侧用分类器同时看推理和行动。公开 Astra 会拒绝部分高级网络请求。Daybreak Blue 是访问计划，不是另一个 Astra 推理模式
- 开发者可带走：长任务的错误处理把「安全中断」做成一等状态，不要当 HTTP 超时重试。需要完整网络能力的防守评测走 Daybreak 申请。监控误伤会进时延 SLO
- 边界与风险：Hugging Face 入侵事件用的不是 Astra（Verge）。TNS 指出「无生产护栏的 Sol」与「有护栏的 Astra」不是干净的 A/B。越界 0% 是该公司内部测试，不是第三方红队报告
- 为何重要：上线日把「更守规矩」和「更难看懂」写在同一份材料里；产品上能立刻碰到的是暂停，而不是那句 AGI

### 6. NVIDIA ModelExpress：DeepSeek-V4 Pro 冷启动从 8 分钟降到 1 分 44 秒
- 类型：工程
- 来源：NVIDIA 技术博客《ModelExpress: Distributing Model Artifacts at the Speed of Light》
- 发布日期：文中未写日历日；TNS 同题稿 2026-09-03，按 24h 收
- 链接：https://developer.nvidia.com/blog/modelexpress-distributing-model-artifacts-at-the-speed-of-light/
- 阅读置信度：全文（官方技术博客）。数字来自 NVIDIA 在 8×B200 + ConnectX-7、vLLM 0.23.0、TP=8 上的自测
- 一句话：MX 在加载前先问「集群里是否已有兼容权重」。有 serving 副本则经 NIXL 做 GPU 到 GPU 的 P2P RDMA；没有则从对象存储流式进 GPU 或走 GPUDirect Storage。DeepSeek-V4 Pro 的权重和 JIT kernel 缓存从副本传到新副本不到 10 秒，端到端启动 8 分钟 → 1 分 44 秒。
- 中心思想：冷启动、扩容、滚动更新和 RL 把新权重送到 rollout worker，付的是同一笔税：权重到位之前不能干活。权重进 GPU 之后，JIT / autotune / CUDA graph 仍可能要几分钟；MX 再用 CPU-to-CPU RDMA 把 Triton、DeepGEMM 等缓存传过去，避免每台都暖一次，也不需要 Kubernetes 的 RWX 盘。
- 关键要点：
  - 路径优先级（能力探测后自动跳过不支持的）：`P2P RDMA -> ModelStreamer -> GDS -> 默认 POSIX 主机暂存`。失败若发生在改模型状态之前会回退；若权重已开始落地，会先重新初始化，避免提供半写入权重
  - 兼容性用 `mx_source_id`（模型 + 决定张量布局的运行时设置）。控制面经 Redis、Kubernetes CRD 或无服务器的 `k8s-service` 发现对端，不经手权重字节
  - 注册开销：默认真对每个 tensor 做 `ibv_reg_mr`。可选 pool registration 按 `cudaMalloc` 分配注册，官方称典型模型少 80%–99% 次；VMM arena 把加载期分配打进一块 16 TiB 虚拟地址，整段一次 dmabuf 注册
  - 集群入口：10 个副本同时拉 806 GiB 的 DeepSeek-V4 Pro 约等于 8 TiB 重复流量；Model Cache Service 用元数据原子认领，只让一个 downloader 跑，其余跟踪进度
  - RL：接收方驱动的 refit——trainer 各 rank 公布自己有的 shard，rollout worker 按目标布局做单边读。博客称 Fireworks/Cursor、Cognition 等已在近期 RL 里用过 delta weight diff（跨集群），MX 在测
  - 集成：原生 vLLM、SGLang；serving 框架含 Dynamo、llm-d。vLLM 0.23.0+ 识别 `--load-format modelexpress`
- 关键数据/指标：不到 10 秒 / 1:44 / 8 分钟 / 806 GiB 为官方自测。GitHub 架构文档另有 DeepSeek-V3 671B FP8、681GB、约 15 秒传输的参考值，测试集不同
- 技术或产品细节：Model Streamer 用多线程按 tensor 范围并发拉取 safetensors，远程读和 GPU 放置流水线化。TP 部署下各 rank 分担远程读，结果通常经 NCCL 共享，而不是每张卡下完整 checkpoint
- 开发者可带走：自建推理池若每副本都从对象存储冷拉，先看是否能让第二副本起走 P2P。vLLM 0.23.0 可试 `--load-format modelexpress`，并单独处理 kernel 缓存，否则权重快了、warmup 仍是几分钟。需要 RoCE/IB/NVLink 等 NIXL 后端，笔记本单机数字套不上
- 边界与风险：数字是 B200 节点、官方配置。无对标 PyTorch 原生 loader 的第三方复测。RL refit「客户正在评估」，不是已 GA 的一键功能
- 为何重要：Agent 流量尖峰按秒来，副本按分钟暖；这一层比再换一个 Flash 型号更直接决定能不能弹性

## 给开发者的思路
1. 编码默认模型这周多了一个 `gpt-6-astra`，但今天多半还叫不到。能进 Trusted Access 的，用同一组仓库任务对比 Fable 5.1、Muse Spark 1.3（非 max）和 `gemini-3.8-flash` 的中/低 effort：标价 Astra 是 Sol 促销价的 2.5 倍，DeepSWE 上几家挤在 74% 附近。打开 Responses API 的 retained reasoning / compaction 和 Codex 笔记开关再比一次，裸 Completions 对不齐官方 ARC 数字。安全中断按一等错误处理，不要当超时重试。
2. 推理扩容和开源分发是另一层。自建 vLLM 0.23+ 池可以试 ModelExpress 的 P2P 权重和 kernel 缓存，把「第二副本从 8 分钟冷拉」当成容量规划问题。Hugging Face 被收购已签约、未交割，CI 先不动；但 8-K 已写开源、尤其是中国来源模型的监管风险，强依赖 Hub 分发的流水线要有备份镜像。
3. 网络能力被拆成三档：ChatGPT/API 默认会拒高级请求并可能停任务；Daybreak Blue/Red 和 Frontline Defenders 补贴才是防御向完整切片。水务、电网、开源维护者走申请，不要用普通 Astra 做 exploit。浏览器自动化则要同时看像素级 Computer Use 和站点 WebMCP——超级 App 若只准备了 GUI，Astra 仍可能点，但不是你能版本约束的接口。
