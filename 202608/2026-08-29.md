### 1. 腾讯发布并开源 Hy4 preview：770B-A49B、1M 上下文
- 类型：工程
- 来源：腾讯官网 + 微信公众号「智东西」（网易号转载）/ 2026-08-28
- 发布日期：2026-08-28
- 链接：https://www.tencent.com/zh-cn/tencent-releases-and-open-sources-tencent-hy4-preview/
- 阅读置信度：全文（架构规格对照 GitHub / DataLearner 对官方模型卡的整理）
- 一句话：腾讯混元 8 月 28 日发布并开源 Hy4 preview；官方把它写成面向真实生产力的早期预览版，而不是正式旗舰定稿。
- 中心思想：相对 Hy3（智东西写 295B / 激活 21B / 256K 上下文），Hy4 preview 扩到总参 770B、每 token 激活 49B、上下文 1,048,576 tokens。官方强调与 CodeBuddy、WorkBuddy 的 Co-Design，以及在软件工程、办公、游戏、科研四类任务上的后训练。
- 关键要点：
  - 腾讯内部盲测：163 名内部专家、203 个工程任务；Hy4 preview 均分 2.99/4，同场 GLM 5.3 为 2.92/4.00、Kimi K3 为 2.94/4.00（厂商自测）
  - WorkBuddy / CodeBuddy 提供两周限时免费；Hy3 在这两款产品上的免费期延长至 9 月 30 日
  - 官方称模型首次参与训练方法、数据策略、评估体系和底层算子的自动优化；推理侧称端到端吞吐相较其基线提升 31.8%
  - 智东西实测（WorkBuddy）：Art Deco 博客站、低多边形 3D 开放世界（约 1 小时、成品约 10MB）、72 份发票合规判断、下载腾讯财报出 PPT；作者写模型有时会困在自我验证循环，需人工打断
  - 已知问题（官方与智东西一致）：复杂任务思考偏长、过度自我验证
- 关键数据/指标：API 中国区每百万 tokens 输入 6 元、输出 18 元、缓存命中最低 0.3 元（官方；智东西称缓存价与 DeepSeek V4 Pro 一致）。DataLearner 转官方附录：SWE-bench Multilingual 82.9、SWE-bench Pro 65.7、Terminal-Bench 2.1 85.4、GPQA Diamond 92.3（厂商评测，受脚手架与工具配置影响）
- 技术或产品细节：MoE，78 层主干（首层稠密 FFN，其余 77 层各 256 个路由专家 + 1 个共享专家，每 token top-8 + 共享专家）；原生 MTP 一层（总参 10B / 激活 0.7B）用于推测解码；注意力为 Gated DSA + IndexCache；残差为四路 Hyper-Connections。权重 Apache 2.0，BF16 与 FP8；HF 上 BF16 约 1.42 TiB、131 个分片。API 型号 `hy4-preview`；推荐 temperature 0.9、top_p 1.0；思考模式 `high`（默认）与 `no_think`。接入：TokenHub、OpenRouter、元宝、ima、CodeBuddy、WorkBuddy。部署示例含 vLLM / SGLang。
- 开发者可带走：先在自有长程仓库任务上对比 `hy4-preview` 与现用 Flash 档，单独记「自我验证过久」是否吃掉超时；本地起服务前先确认多卡容量，不要按单卡 Flash 的习惯估。
- 边界与风险：盲测与附录榜单均为腾讯口径；智东西样例不是统一基准。preview 不等于正式版。Blaschke–Lebesgue 体积下界等科研数字见智通财经转述，本文以官网已写明的 31.8% 吞吐为准。
- 为何重要：GLM / Qwen Flash 之后，国内又多了一个可商用开源、主打生产力脚手架的 770B 档选项。

### 2. Anthropic 开放 Model Hardware Standard 研究预览
- 类型：工程
- 来源：Anthropic 官网 / 2026-08-27
- 发布日期：2026-08-27
- 链接：https://www.anthropic.com/news/model-hardware-standard-research-preview
- 阅读置信度：全文
- 一句话：MHS 是给 AI Agent 操作实验室与产线设备用的驱动规范，目前只对申请通过的科研与制造伙伴开放，计划在预览之后开源。
- 中心思想：实验室里显微镜、移液工作站、机械臂往往各用各的程序、互不通讯，集成要数周到数月。MHS 用标准化驱动把设备变成可发现的「读 / 写」原语，Agent 再通过 MCP、命令行或 API 代码文件编排。协议与模型无关，不绑定 Claude。开发起点是 Anthropic 与 HHMI Janelia 的合作。
- 关键要点：
  - 驱动里可用自然语言标签写入说明书里才有的物理约束（例如机械臂重量），再自动生成设备参考文件
  - 长任务可把多步驱动命令打成代码文件，让设备自己跑，而不必每一步都走在线推理
  - 官方举例：Claude 调激光、用相机看光斑、再把学到的流程写成确定性脚本
  - 伙伴案例：Genentech 用移液工作站 + 机械臂 + 酶标仪做 BCA 蛋白定量；卡内基梅隆称剂量–反应串稀释实验约快 3 倍；QuEra 称激光锁频在无人工干预下恢复成功率 99.3%（The Register 另写此前约 58%）
  - 硬件/软件厂商计划接入：AWS Strands Robots、Automata LINQ、Doosan、Tecan Fluent、Universal Robots、QIAGEN、MBF ScanImage 等；Hugging Face 计划在 LeRobot 中加 MHS，Raspberry Pi 在 Camera MHS Driver 测试后跟进
- 关键数据/指标：CMU「约 3 倍」与 QuEra 99.3% 为合作方/官方转述的单点实验，不是跨实验室基准
- 技术或产品细节：只支持已有可编程接口的设备；无接口硬件还需厂商补驱动。控制路径三条：MCP、CLI、代码 API。申请入口在官网预览页。
- 开发者可带走：若实验室已有可编程接口，可排队预览，先把安全限位写进驱动标签，而不是写进 prompt。没有接口的旧设备现在接不上。
- 边界与风险：官方承认 LLM 缺乏物理直觉，仍需专家盯场；Genentech 需人工告诉模型「样品起泡是物理失败不是软件 bug」。开源时间表未给。The Register 提醒：模型行为本身仍不可完全预知。
- 为何重要：MCP 之后，Anthropic 把「工具」从软件 API 扩到真实仪器，安全评测会从文本越狱变成物理误操作。

### 3. Google DeepMind 试点专有模型的双盲评测
- 类型：工程
- 来源：Google DeepMind 官方博客 / 2026-08-27
- 发布日期：2026-08-27
- 链接：https://deepmind.google/blog/piloting-the-worlds-first-double-blind-ai-evaluations/
- 阅读置信度：全文（对照 TechRepublic、AVERI 试点说明）
- 一句话：在 Google Cloud Confidential Space 里同时封存 Gemini 权重与外部方的保密题，让评测方看不到权重、Google 看不到原题。
- 中心思想：以往高风险外评只能二选一：把题交给模型厂，或把权重交给评测方。这次试点声称用硬件加密飞地取消这个交换。合作方包括新加坡 AISI、OpenMined、AVERI、MLCommons。官方写明目的是提高评测完整性，而不是公布 Gemini 分数。
- 关键要点：
  - 受试模型：Gemini 2.5 Flash Lite（能放进单卡显存的生产级模型，不是旗舰）
  - 题目：MLCommons AILuminate 预留集（AVERI）；新加坡 AISI 另有本地有害内容题
  - 硬件：Google Cloud A3 Confidential VM，Intel TDX 主机内存加密 + NVIDIA H100 Confidential GPU
  - OpenMined PySyft 做代码预审与断外网；双方先远程证明飞地软件再送数据
  - TechRepublic 转述技术报告：加密层开销小于 5%；更大阻力是跨机构法律协议和联合代码审查
- 关键数据/指标：开销「<5%」为 Google 技术报告口径。官方博客与技术报告均未公布 Flash Lite 得分
- 技术或产品细节：评测结束只返回允许的结果，临时环境销毁。信任并未清零：Confidential Space 客户 OS 开源，但构建签名与证明服务仍走 Google；部分专有推理代码无法完全进允许名单。单卡 H100 飞地尚不能评需要多卡推理的旗舰模型
- 开发者可带走：采购或验收若仍只看公开榜，至少要求对方说明题目是否对训练不可见；这条试点证明「保密题 + 不交权重」在工程上可做，但目前只覆盖单卡模型。
- 边界与风险：「全球首个」是 DeepMind 自己的表述。多卡加密链路尚未作为生产评测工具交付。MLCommons 提醒：题面保密解决不了题目本身设计差的问题。
- 为何重要：把基准污染从合同承诺推进到可验证的硬件隔离，这是监管与采购真正缺的那一层。

### 4. Claude Cowork 桌面端内置浏览器：与用户浏览器拆开
- 类型：工程
- 来源：Anthropic 官方博文（https://claude.com/blog/cowork-built-in-browser）；中文对照「智东西」/凤凰网、Cocoloop / 约 2026-08-26–08-27
- 发布日期：中文报道 2026-08-27
- 链接：https://claude.com/blog/cowork-built-in-browser
- 阅读置信度：全文（官方页抓取超时，细节以官方博文转述与智东西、Cocoloop 对照；若与官网后续修订不一致，以官网为准）
- 一句话：Cowork 任务碰到网页时，在桌面应用侧边栏打开 Claude 自己的浏览器，无需再装扩展；这与「Claude in Chrome」不是同一条路径。
- 中心思想：以前要让 Cowork 操作网页，只能把用户的 Chrome 交给扩展。很多任务其实只需要「一个浏览器」，不需要用户的标签页和密码。内置浏览器默认看不到用户的书签、标签和已存密码。已在用 Chrome 扩展的用户仍以扩展为默认，可在 Settings → Cowork → Preferred browser 切换。
- 关键要点：
  - 推送：未来一周面向桌面端 Pro / Max / Team（macOS、Windows、Linux 为 beta）；到位后默认开启。Enterprise 现已可用，管理员在组织设置里管
  - 登录导入：macOS 可从 Chrome、Edge、Firefox 按站点导入；Windows / Linux 目前报道写的是 Firefox。银行、邮箱、SSO 默认不导入，除非用户主动选入
  - 网页版或手机要驱动内置浏览器，前提是桌面应用开着且在线；没有桌面应用时仍走 Claude in Chrome
  - 官方建议：内置浏览器适合调研、供应商门户抓发票这类「交给 Claude 去办」的活；Chrome 扩展适合 CRM、收件箱等「页面已经开着」的活
  - 安全：沿用 Claude in Chrome 的提示注入对照（行动是否仍符合原始任务）；官方原话转述为能明显降低风险但不能消除，建议先从可信站点用起
- 关键数据/指标：Gate 等转述红队数字（Sonnet 5 / Opus 5 提示注入成功率 0%，Fable 5 为 0.3%）未在本次已读中文稿中看到官方原文，待核实
- 技术或产品细节：无扩展、无额外安装。Anthropic 没有用内置浏览器替换扩展，而是并存两条通道。
- 开发者可带走：企业试点先禁止导入 SSO/邮箱，把内置浏览器限定在无登录或只读站点；需要操作用户已登录会话时才开 Chrome 扩展。
- 边界与风险：提示注入没有被说成已解决。执行进程在用户本机，桌面应用离线则网页端开不了这条通道。
- 为何重要：豆包工作、ChatGPT Work 之后，Claude 把「Agent 的浏览器」和「人的浏览器」拆成两个进程，权限模型比共用扩展更清楚。

### 5. Meta MTIA 300：把网卡和集合通信做进推荐训练加速卡
- 类型：工程
- 来源：InfoQ / 2026-08
- 发布日期：文内为 2026 年 8 月（URL 路径 `/2026/08/meta-hccl/`，精确日待核实）
- 链接：https://www.infoq.com/news/2026/08/meta-hccl/
- 阅读置信度：全文
- 一句话：MTIA 300 是 Meta 第一款面向排序/推荐训练的自研加速卡，重点不是峰值算力，而是把通信从 PCIe 和通用 GPU 计算资源里拆出去。
- 中心思想：Meta 称推荐模型参数里超过 99% 在 embedding 表，训练时大量 AllReduce / AllToAll / AllGather，网络会变成瓶颈。MTIA 300 把网卡放进加速器封装，并用独立 message engine 做集合通信，让大矩阵计算和通信重叠。
- 关键要点：
  - 两颗网络 chiplet，各 6 个定制 800 Gbps RDMA NIC，共 12 口、合计 1.2 TB/s I/O，不经过 PCIe
  - 同一组 NIC 同时服务机架内 scale-up 和机架间 scale-out
  - 16 个专用 message engine，含近内存 reduction；Meta 称计算与通信并发时算力下降小于 0.5%，对照 GPU 架构上重叠时下降超过 20%（Meta 自测）
  - 集合库 HCCL 把集合操作编译成加速器可自主执行的子图，运行期不再由主机 CPU 逐步驱动
  - 生产口径：HCCL 机架内通信带宽最高约 940 GB/s；1500 亿参数推荐模型、40 卡规模，通信时间相对等价 GPU 集群降 3.9 倍（Meta 口径）
- 关键数据/指标：1.2 TB/s I/O；940 GB/s；3.9× 通信时间（均为 Meta / InfoQ 转述）
- 技术或产品细节：已有数十万颗 MTIA 做推理；未来两年还规划四代，覆盖排序、推荐和生成式。与 Broadcom 扩大合作开发后续 MTIA，同时继续买 AMD、NVIDIA 等，官方称 portfolio 策略
- 开发者可带走：自研硅的叙事不要直接套到 LLM 训练；这条卡的设计假设是 embedding 通信主导。外部开发者目前看不到可购买的 MTIA 云实例说明。
- 边界与风险：全部为厂商生产数据；精确发布日 InfoQ 未在正文写死。不能据此宣称通用 GPU 已被替代。
- 为何重要：和本周英伟达、OpenAI 自研推理芯片新闻对照，超大规模厂把定制硅从计算扩到网络。

## 给开发者的思路
1. 国产开源这一周的可比对象换成 Hy4 preview：用同一组带工具的仓库任务对比 `hy4-preview`、GLM-5.3-Flash、Qwen3.8-Flash，记录成功率、自我验证超时和每百万 tokens 账单（Hy4 输入 6 元 / 输出 18 元，缓存 0.3 元）。内部盲测分不要当 SLA。

3. 供应链与账号：Hugging Face 收购尚未公告，但 Hub、私有数据集和推理 Endpoints 已是单点依赖。英伟达单季利润和 Q3 指引说明 GPU 供给故事仍在加速；同时为 Agent 建机器身份（而不是共用员工账号）已经出现在 Okta 的预订结构里，比等 A 股主题票更值得进迭代计划。
